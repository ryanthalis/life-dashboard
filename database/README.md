# Database schema changes

SQLAlchemy models describe the application schema, and Alembic records each
versioned change under `database/migrations/versions/`. Do not maintain a second
set of table-creation SQL files.

From the repository root, apply all pending changes with:

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
```

Create a candidate migration after changing the models with:

```powershell
.\.venv\Scripts\python.exe -m alembic revision --autogenerate -m "describe change"
```

Always review autogenerated operations before applying them. Autogeneration is
a comparison aid, not proof that a migration preserves the intended data and
constraints.
